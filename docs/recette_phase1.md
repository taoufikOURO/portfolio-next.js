## 5. Procédure proposée : sauvegarde, reset, seed et reconnexion

**Rien de ceci n'est lancé avant l'accord de Taoufik sur ce document.** Chaque commande de Claude est annoncée avant d'être exécutée.

1. **Dossier de sauvegarde** : `E:\DEV\sauvegardes\portfolio\` (décision de Taoufik, E59), **hors du dépôt**. **Aucune copie de `.env`** n'y est faite. Le fichier contient les données de la base locale, dont le hash du mot de passe administrateur : il ne doit jamais entrer dans le dépôt.
2. **Sauvegarde** : `pg_dump` (format personnalisé, `C:\Program Files\PostgreSQL\18\bin\pg_dump.exe` présent) lancé par un script jetable hors du dépôt via `node --env-file=.env` : le processus lit `DATABASE_URL`, Claude ne lit pas `.env`. Le script retire les paramètres propres à Prisma (par exemple `?schema=`) que PostgreSQL refuse, ne journalise ni URL ni mot de passe, et refuse tout hôte qui n'est pas local. Variante au choix de Taoufik : il lance `pg_dump` lui-même avec `!`.
3. **Contrôle de la sauvegarde** : code de sortie 0, fichier non vide, `pg_restore --list` réussit et cite les tables attendues, comptage des lignes par table pris juste avant et consigné (aucune donnée affichée). **Une seule de ces conditions en échec : arrêt, pas de reset.** Option : restauration d'essai dans une base temporaire `portfolio_verif` (création d'une base : seulement avec l'accord de Taoufik).
4. **Consentement Prisma (E32)** : Claude annonce la commande, la base visée (locale `portfolio`) et la perte des données ; Taoufik répond ; Claude lance `pnpm db:reset` avec `PRISMA_USER_CONSENT_FOR_DANGEROUS_AI_ACTION` contenant cette réponse. Le garde-fou de `prisma.config.ts` refuse toute `DIRECT_URL` non locale.
5. **Après le reset** : `pnpm prisma migrate status` (à jour) et `prisma migrate diff` (aucun écart). À ma connaissance, Prisma 7 ne relance pas le seed tout seul après `migrate reset` ; la sortie du reset le confirmera. S'il se lançait, il échouerait proprement sans `ADMIN_PASSWORD` (message qui nomme la variable, rien d'écrit).
6. **Seed, par Taoufik dans son propre terminal PowerShell** (pas avec `!` dans cette session : la commande et sa sortie entreraient dans la conversation, mot de passe compris) :
   `$env:ADMIN_PASSWORD = '<son mot de passe, 12 caractères minimum>'; pnpm db:seed`
   puis fermeture du terminal. La variable n'existe que dans cette session. Le seed lit `ADMIN_EMAIL` dans `.env`, crée le compte (adresse en minuscules, mot de passe haché argon2id) et le profil vide. **`ADMIN_PASSWORD` n'est jamais écrit dans `.env` ni dans un fichier** (le plan note qu'il en avait été retiré à l'étape 7 ; il n'est pas relu ici).
7. **Reconnexion (ligne 9.5)** : le reset a supprimé les sessions, donc le cookie actuel de Taoufik ne vaut plus rien.
